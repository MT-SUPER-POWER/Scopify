统一组织字段标签、控件、说明与错误信息。上方示例直接渲染 `@scopify/ui` 中的真实组件，可以操作并观察其状态变化。

## 安装

该组件已经通过 shadcn CLI 安装在共享 UI 包。需要与上游重新同步时，在仓库根目录运行：

```bash
cd repo/frontend/packages/ui
bunx shadcn@latest add field
```

CLI 文件属于 `shadcn/` vendor 层；产品特有扩展应放在 `scopify/`，不要直接改写原生实现。

## 导入

```tsx
import {
  Field,
  FieldLabel,
  FieldDescription,
  FieldError,
  FieldGroup,
  FieldLegend,
  FieldSeparator,
  FieldSet,
  FieldContent,
  FieldTitle,
} from "@scopify/ui/shadcn/components/field";
```

## 用法

下面是上方交互预览的核心结构。业务状态、路由、请求和 i18n 仍由消费层提供。

```tsx
<Field className="w-full max-w-sm">
  <FieldLabel htmlFor="preview-playlist-name">歌单名称</FieldLabel>
  <Input id="preview-playlist-name" defaultValue="晚间漫游" />
  <FieldDescription>名称会显示在你的公开主页中。</FieldDescription>
</Field>
```

## 常见用法

- 统一标签、控件、说明与错误。
- 用 FieldGroup 排列相关字段。
- 错误信息与 aria-invalid 保持一致。

## 使用建议

- 每个控件都要有可访问标签，并在错误时同步 aria-invalid 与错误文本。
- 受控值、校验和提交逻辑由消费层管理，基础组件不耦合具体表单模型。
- 使用单一状态来源，避免同时传入 value 与 defaultValue。

## API 参考

当前模块公开 `Field`、`FieldLabel`、`FieldDescription`、`FieldError`、`FieldGroup`、`FieldLegend`、`FieldSeparator`、`FieldSet`、`FieldContent`、`FieldTitle`。实际 props 继承自对应的 Radix primitive 或原生 HTML 元素，并叠加 shadcn 的样式与 slot 约定。

完整的交互模式、可访问性说明和底层 props 请查看 [shadcn/ui Field 表单字段 文档](https://ui.shadcn.com/docs/components/radix/field)；实现差异以本仓库当前 CLI 源码为准。
