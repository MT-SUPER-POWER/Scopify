## 版本号规则

Scopify 使用 `x.y.z` 版本格式：

| 位置 | 含义 |
| --- | --- |
| `x` | 重大更新，可能包含不兼容修改 |
| `y` | 向后兼容的新功能 |
| `z` | Bug 修复与小型改进 |

## Release 检查

发布 Tag 前建议验证容器配置与完整运行环境：

```bash
docker compose config --quiet
docker compose up -d --build
```

随后检查 Web 与后端地址是否可以正常访问。GitHub Actions 会在推送 `v*` Tag 时构建安装包，并从 `docs/CHANGELOG.md` 中提取同名版本标题作为 Release Notes。

例如发布 `v1.0.5` 前，版本日志中应存在：

```md
## v1.0.5
```

桌面打包流程会递归获取后端 submodule，用于准备可选的内置后端资源。
