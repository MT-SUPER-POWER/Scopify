这次仅建立一个小案例供评审，尚未替换现有播放器或平台接口。

## 三层类型

```text
网易云 API DTO ─→ adaptNeteaseTrack ─┐
                                  ├→ @scopify/music-domain 的 MusicTrack → 界面 Props
QQ API DTO ────→ adaptQqTrack ──────┘
```

平台 DTO 留在 Web 的 `types/providers/`，只描述本次使用的原生字段。适配器放 `lib/music/providers/`，不把转换塞进请求函数或组件。领域包不依赖任何应用，界面 Props、模拟队列和展示文案留在 Docs 应用。

## 可以验证什么

1. 两首曲目的数字 ID 都为 101，QQ 仍按 MID 定位，不会覆盖网易云资源。
2. 加入两个来源的歌曲，切换身份，混合队列和模拟当前曲目保持不变。
3. 用网易云身份喜欢网易云样本，切到 QQ 后侧栏切换、收藏不串号，云盘入口消失。
4. 切回网易云，个人喜欢状态恢复；切换身份不会改写曲目的公共信息。
5. 当前身份不能直接收藏另一来源的曲目，不隐式借用另一个账号。

Demo 中“未收藏”来自已知的本地初始状态，不能作为真实接口尚未返回时的默认值。真实接入还需增加未知、加载失败和无权限等操作状态。

## 当前不做什么

这一步不接真实 API、不移动已有歌曲类型、不迁移播放器、不同步资产，也不引入自动换源、跨平台歌单转换或账号持久化。固定样本只证明类型分层与交互边界，不证明上游接口或播放权限可用。

待评审通过后，再按业务区域扩展领域模型与适配器，逐步替换旧类型。
