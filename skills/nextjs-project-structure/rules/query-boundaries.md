# Query 与错误边界

请求状态由 TanStack Query 管理；失败影响范围由 React 组件边界决定。此规范适用于 Web 和 Electron renderer。检查范围以根 AGENTS.md 为准。

## 选择边界

| 边界 | 示例 | 恢复范围 |
| --- | --- | --- |
| 应用兜底 | 根布局、初始化、未预期运行时异常 | 应用级错误页 |
| 页面主内容 | 歌单、专辑、MV 主详情 | 页面内容区；保留应用外壳和播放栏 |
| 独立栏目 | 首页推荐、排行榜、相似 MV、评论 | 对应栏目 |
| 分页 | 下一页、加载更多 | 列表尾部；保留已经加载的数据 |
| 用户操作 | 收藏、点赞、发表评论 | 操作附近反馈、必要时回滚 |
| 媒体 | 播放地址请求、video/audio 加载失败 | 播放器内部；保留详情与评论 |

必须一起成功才能使用的请求共用边界；可独立使用的内容拆分边界。不能按请求个数机械拆分，也不能给每张卡片增加无意义边界。

## 数据流与目录

- `lib/api/`：发请求，声明预期业务码；请求失败继续 reject，不吞错。
- `lib/web/`：复用现有 ApiError 分类、会话失效处理和日志基础设施。
- `hooks/<领域>/`：Query key、请求条件、缓存和错误抛出策略；数据适配放业务纯函数。不得汇总多个独立 Query 的 isError/isFetching 决定整页状态。
- `components/<领域>/`：边界外做组装；边界内的数据容器调用对应 Query，再渲染展示组件。
- `components/shared/`：统一 Query 边界、错误分类后的 fallback 与重试。网络提示组件保持纯展示职责。
- Props、策略和错误类型放 `types/`；通用策略放 `lib/query/`。

Query 必须在对应边界的子组件中调用。父组件已经调用 Query 后，再给下面的展示组件套边界，无法接住父组件抛出的错误。

## 状态协议

1. 首次无数据且正在请求：显示该区域骨架屏。
2. 首次无数据且请求失败：使用 `throwOnError` 抛给最近的边界。
3. 已有缓存数据，后台刷新中或刷新失败：保持内容，不切回骨架或错误页。数据是否存在以 `data !== undefined` 判断，不能以数组长度判断。
4. 成功返回空数组或合法空结果：显示业务空状态，不视为错误。数据形状损坏不能当作合法空结果。
5. 因离线等待网络（fetchStatus paused）、请求取消或 enabled=false：不伪造网络错误，不一直显示正在联网请求。
6. 加载更多失败：保留已有列表，在尾部重试该页；首次加载失败仍交给区域边界。
7. Mutation 默认不抛给页面边界；反馈归所属操作，乐观修改需要回滚。收藏状态未获取时应保留“未知/不可操作”，不能显示成未收藏。
8. 媒体元素错误通过其事件进入播放器本地状态；普通 React 错误边界不会自动接住媒体事件失败。

新迁移的读取 Query 复用统一的“无数据才抛出”策略。不要直接全局开启 throwOnError 影响尚未迁移的页面。

## 错误与重试

- 网络、超时、后端服务失败：区域网络重试组件。
- 已知资源不存在、无权限：业务状态；不能全部写成网络错误。
- 会话失效：现有集中登录处理；不要重复弹窗。
- 程序异常、未知错误：未预期错误组件与诊断记录；不要伪装网络失败。
- 每个独立恢复区域组合 `QueryErrorResetBoundary` 和 React 错误边界。重试要同时恢复两者；默认只重试该边界内失败的读取。
- 资源身份变化（页面 ID、搜索词/Tab）重置对应边界，不能将旧资源的错误沿用到新资源；不要使用每次渲染都新建的对象作为无条件重置触发器。
- QueryCache.onError / MutationCache.onError 用于统一记录。避免请求层、Query 层、边界和业务组件重复弹出同一错误。

不强制迁移到 Suspense。普通 useQuery 配合 throwOnError 已能接入；含条件请求的 hook 不可直接替换成不支持 enabled 的 useSuspenseQuery。若同一边界使用多个 Suspense 查询，注意请求瀑布和并行策略。

## 禁止与迁移

- 禁止 `queryA.isError || queryB.isError` 将独立区域合成为整页失败。
- 禁止 catch 后返回 `[]`、`null`、默认收藏状态伪装成功。
- 禁止用后台 isFetching 抹掉现有内容。
- 禁止把分页、收藏、评论或播放失败升级成整页不可用。
- 禁止继续增加页面专用的失败栏目清单、全局 refetch 聚合器，或复制一套错误重试状态机。

迁移时先标明核心、可选和依赖请求，再接入共用基础设施，最后删除旧聚合状态及只验证旧实现的测试。保留业务转换、播放行为、账号隔离、分页 key 和已有 fallback 语义；允许在同一业务单元内明确声明备用数据源，不能隐式吞错。

定向验证首次失败重试、缓存刷新失败、局部失败、资源切换、分页追加失败；按实际改动选择必要场景。源代码/单测/钩子/真实 UI 与接口验证分别报告，不能相互替代。

官方参考：[错误传播与缓存](https://tanstack.com/query/latest/docs/framework/react/guides/suspense#throwonerror-default)、[边界恢复范例](https://tanstack.com/query/latest/docs/framework/react/guides/suspense#resetting-error-boundaries)。
