# 用户动态与个人主页落地

2026-09-24 · 分支 `codex/profile-social-design`

## 已实现范围

以已确认的融合稿为基础，将动态流与个人音乐主页接入现有 Scopify Shell。主题色、侧栏、全局顶栏与底部播放器继续使用现有应用能力。

- 侧栏「动态」与顶栏好友按钮进入 `/social`；朋友动态使用 `/event`，自动加载下一页，也保留手动加载与失败重试。
- 发布文字、搜索歌曲/歌单附件、分享正在播放的歌曲、转发、动态点赞与本人删除；所有写操作等待业务成功再更新状态，失败保留输入。
- 点击作者进入 `/profile?userId=用户ID`。本人主页可以编辑资料、发布动态和进入最近播放；他人主页可以关注、取消关注和私信。
- 主页包含真实横幅、头像、签名、关注/粉丝，以及「动态 / 歌单 / 关于」。个人动态通过目标用户 ID 单独分页，不使用自己的动态代替他人的内容。
- 歌单区展示接口允许访问的创建/收藏歌单，并提供分页。关注、粉丝列表与用户搜索可继续进入其他人的主页。
- 动态详情 `/social/event?id=动态ID&uid=作者ID` 支持评论、回复、评论点赞和删除本人评论；动态互动统一使用完整 `threadId`。
- 歌曲、歌单与专辑附件接入现有播放器和队列。没有为动态创建第二套音频播放逻辑。
- 私信弹窗读取对话历史、加载更早消息、发送文字，并在打开时每 30 秒拉取；发送失败不清空草稿。
- 通知新增可选结构化目标。有明确动态标识时进入详情，私信进入对应用户对话，只有明确用户标识时进入主页；未知目标保持摘要。
- 简体中文、繁体中文、英文文案；键盘可操作的按钮、弹窗焦点约束与关闭交互；窄容器下收起右侧栏、将个人名片改为纵向排列。

## 数据与状态

请求集中于 `lib/api/social.ts`，解析集中于 `lib/social/normalize.ts`，查询/写操作由 `hooks/social/` 管理。路由仅负责装配组件。

React Query 按登录账号与登录方式隔离缓存，动态、详情、个人资料、关系、评论和私信分别建键。点赞/删除会同步已缓存的首页、个人动态及详情；关注操作更新关联资料与关系列表。页面复用现有 RouteScrollSurface，浏览器返回沿用应用滚动恢复。

只读取服务端公开或当前账号有权限访问的内容；不伪造朋友在线、一起听或实时收听信息，不请求他人的私有最近播放。

## 当前接口边界

- 未确认动态图片上传接口；发布器支持文字、歌曲、歌单，已存在动态中的图片支持浏览。
- 不将朋友动态标成算法推荐。后端没有可靠的独立推荐/关注筛选契约。
- 暂未确认单条动态查询接口。详情优先复用已浏览内容；直接进入时最多读取作者 5 页动态。超过范围、已删除或受限的内容显示暂不可用，并提供主页入口。
- 视频/播客等附件保留可识别信息，不虚构当前播放器不支持的播放按钮。
- 通知定位字段只在后续同步获得，历史摘要若没有定位信息不猜测目标。
- 上游依然决定登录权限、可见性、资源播放权限及写入结果。
