# 登录设备 API 接入

已在第一套展示台布局上替换示例数据，通过用户头像菜单进入。设备页不再注册设置 Tab。

## 数据与交互

- `/device/list`：读取 `data.userDeviceList` 和 `userDeviceLimitInfoDTO`。额度使用服务端 `currentNum/deviceLimit`，不使用记录总数替代。缺少额度时不展示假数值。
- `ifLoginDevice === true` 标识当前设备；时间按毫秒格式化，未知地区、平台和活动时间保留中性文案。不推测在线/离线枚举。
- 展示台显示当前设备与最近记录（最多四台），列表展开其余记录；最近活动页按时间排列。设备图形用于区分类别，不宣称准确识别硬件型号。
- `/deviceinfo/center/upload`：仅当前设备可改名，成功后刷新列表并记住本地名称。名称为 1–80 字符的界面约束。
- `/device/kickoff`：传入 `deviceKey`，而非文档中的 `key`；确认后执行，成功刷新。当前设备另有退出账号提示，成功后清理本地会话和账号查询缓存。
- 安全验证：用户主动展开验证码输入并发送时调用 `/captcha/safe/sent`，再将验证码作为 `captcha` 传入下线请求；没有猜测业务码自动发送短信。上游是否要求安全码及具体错误仍由真实服务响应决定。

## 登录时名称与身份

扫码和手机号登录在确认账号身份之后调用共用完成流程，上报用户在登录页填写的设备名称。默认名称区分 Scopify/Web 和粗粒度系统。名称上报最多等待五秒，失败不阻止完成登录，并提示在设备页重试修改名称。

新登录使用每个安装/浏览器配置中持久保存的随机 `deviceId` 和已识别的 `os`，通过后端明确读取的 Cookie 字段传递；二维码生成、轮询与保存后的会话沿用同一个标识。仅绑定新登录，不改写旧会话、导入 Cookie 或任意其他设备。上传接口仍只接收名称，未伪造 CPU、系统版本或官方客户端版本，也未默认读取系统主机名。

## 状态与边界

设备查询通过 TanStack Query 管理，随账号、会话和后端变化隔离；原始 Cookie 不进入查询 key，设备数据不持久化。加载、空列表、请求失败、刷新失败及未登录分别呈现。切换会话关闭原会话的选择与操作面板，写操作完成后再次核对会话。

接口类型、请求封装、数据 hook、展示适配与组件分别放在 `types/api`、`lib/api`、`hooks/devices`、`lib/devices` 和 `components/devices`。二维码状态移至 `hooks/auth/useQrLogin.ts`。

本轮只完成源码接入与局部格式化；没有运行测试、构建或真实账号写操作。短信、改名、下线和不同登录方式的上游可用性尚未联调，之前的视觉 QA 不覆盖这些操作。
