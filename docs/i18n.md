# 国际化开发

Web 和桌面渲染器共用 `repo/frontend/apps/web/locales/` 下的翻译，按语言和业务命名空间拆分：

```text
locales/
  zh-CN/common.json    # 源语言：通用文案
  zh-CN/playlist.json  # 源语言：歌单文案
  zh-TW/common.json
  en-US/common.json
  resources.ts         # 向 i18next 注册各语言的命名空间
```

文件内使用平铺键，例如 `common.json` 的 `action.confirm`；代码中通过 `useI18n().t("common.action.confirm")` 或 `translate(locale, "common.action.confirm")` 使用。第一段是业务命名空间，余下部分是文件中的键；插值使用 `{{name}}`。

翻译运行时使用 [i18next](https://www.i18next.com/)，缺失时回退到简体中文。语言选择由设置中的 Zustand 状态持久化；翻译时显式传入语言，不依赖共享的全局语言状态。资源当前随应用一起加载，按文件拆分不等于按需加载。

新增文案时，在三种语言对应的业务文件中填写相同键及占位符。如果新增业务命名空间，还需为三种语言各建 JSON，并在 `resources.ts` 中导入和注册；翻译键类型从注册的简体中文资源推导。i18next 官方 CLI 会生成 `types/i18n/resources.generated.d.ts`：启动 Web 开发服务时自动生成并监听源语言文件，Web 和桌面构建及类型检查前也会自动更新。直接编辑生成文件无效。未启动开发服务时，文案修改会在下次启动、构建或类型检查时同步。

## 使用 x18n

[x18n](https://github.com/x18n-dev/x18n) 直接读写这些 JSON 文件。在仓库根目录执行：

```sh
bun run i18n:x18n                       # 语言和翻译概览
bun run i18n:x18n:ui                    # 打开翻译管理界面
bun run i18n:x18n get common.action.confirm
bun run i18n:x18n usages common.action.confirm
bun run i18n:x18n check                 # 检查翻译、占位符和使用情况
bun run i18n:x18n extract --list        # 查找待翻译的硬编码文案
```

也可以安装 x18n VS Code 扩展，使用仓库根目录的配置显示翻译、跳转和引用。UI 和编辑器对翻译的修改会直接写入正式资源；重命名或提取也会修改代码，请检查产生的差异。`repo/frontend/apps/web/` 中的 `pnpm run i18n:audit` 是硬编码文案候选列表的快捷入口。

x18n 的静态扫描无法完整识别动态拼接的键、间接传递的翻译函数等用法，可能将这些键标记为未使用；删除前须检查代码。
